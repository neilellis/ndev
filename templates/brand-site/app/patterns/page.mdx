# Patterns

How to choose the way to show a set of facts. Pick the lightest pattern that does the job. A table is the last choice.

<Rule>
This ladder is a recommendation. Each pattern points to a component that the website already uses. The examples are from the website.
</Rule>

## The ladder

| The job | Pattern | Component |
|---|---|---|
| One idea, said plainly | A statement with the signature move | [Section heading](/components) |
| One or two facts to read | A sentence | Body text |
| A few parallel offers | Numbered, ruled columns | [Service columns](/components) |
| Items with a short label | A label column beside the text | Experience list, case-study sections |
| A reading list in order | A numbered series | [Articles](/components) |
| One item to feature | A featured article or a pull quote | [Articles](/components), [Quote](/components) |
| Many records compared on the same fields | A table | Last choice |

A sentence such as “We bring the expertise, evidence and practical experience to move your business forward.” is better than a list of three nouns.

## Compose for rhythm

A page is a sequence of bands. Start with a heading and one idea, then the detail, then one action. Alternate paper, mist and navy surfaces. See [Page sections](/sections).

## If you need a table

- Use it only when the reader compares many items on the same fields.
- Use hairline rules between rows. No vertical lines. No zebra stripes.
- Put the key column first. Right-align numbers.
- Use small capitals for the header row, in `--text-muted`.
- On a phone, let the table scroll inside its own container. Do not let the page scroll sideways.
- Write an empty state in words, for example “No case studies in this sector yet.” This example is placeholder copy.
